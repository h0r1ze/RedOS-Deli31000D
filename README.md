# Deli M3100D в Linux: печать и сканирование

Комплект для запуска МФУ **Deli M3100D** (USB `300e:10c4`) под Linux —
собран под РЕД ОС 8 (`redos`, родня RHEL 8), но ничего специфичного для неё
в нём нет: заработает на любом дистрибутиве с CUPS и SANE.

В комплекте: PPD-файлы и фильтр CUPS для печати, патч к свободному
SANE-backend для сканера, скрипты установки и, самое главное, диагностика —
она определяет, какая из веток подходит именно вашему аппарату.

## Почему начинать нужно с диагностики

Deli не публикует драйверов для Linux (в открытом доступе — только пакеты
для Windows), а в `sane-backends` устройств Deli нет вовсе: в таблице
`xerox_mfp.conf` перечислены только Samsung, Xerox и Dell. Поэтому заранее
неизвестно, на каком языке аппарат принимает задание на печать (PCL-XL,
PCL5, PostScript или собственный растровый поток) и на каком протоколе
разговаривает сканер.

Устройство само об этом рассказывает — надо только спросить. Этим и заняты
скрипты в `tools/`: они читают строку IEEE-1284 Device ID, разбирают
USB-дескрипторы и стучатся к сканеру. По их ответам выбирается ветка.

## Быстрый старт

```sh
git clone <этот репозиторий> && cd RedOS-Deli31000D

# 1. снять данные с аппарата (ничего не меняет, отчёт кладётся в файл)
sudo ./tools/deli-probe.sh

# 2. печать: PPD подбирается по строке Device ID
sudo ./install-printer.sh
lp -d Deli-M3100D /usr/share/cups/data/testprint

# 3. сканирование: сначала проверка протокола, потом сборка backend
sudo ./tools/deli-asp-probe.py
sudo ./install-scanner.sh
scanimage -d pantum --mode Gray --resolution 300 --format=png -o /tmp/scan.png
```

Если на шаге 2 из принтера вышел мусор или ничего не вышло — язык печати
определён неверно, прогоните `sudo ./tools/deli-pdl-test.sh`: он по очереди
шлёт короткие задания на четырёх языках, и вы просто смотрите, после какого
из них выехала нормальная страница.

## Как устроена печать

CUPS приводит любое задание к PDF, дальше его забирает `deli-rasterize` и
отдаёт Ghostscript, который собирает готовый поток на языке принтера. Какое
устройство Ghostscript использовать, написано в самом PPD строкой
`*DeliGSDevice` — поэтому один фильтр обслуживает все три варианта, а
добавить четвёртый можно, не трогая код.

Поддерживаются размер бумаги (7 стандартных плюс произвольный), разрешение
300/600/1200 и двусторонняя печать. Для PCL-XL дуплекс включает сам
Ghostscript, для PCL5 — фильтр, командой `ESC&l1S`, потому что `ljet4` её не
выдаёт.

Подробности и что делать, если аппарат окажется растровым (GDI/ZjStream), —
в [docs/02-printing.md](docs/02-printing.md).

## Как устроено сканирование

Сканер у таких МФУ висит на отдельном vendor-специфичном интерфейсе USB и
говорит на собственном протоколе. Для родственных аппаратов Pantum M6500
этот протокол разобран и опубликован в проекте
[pantum-open](https://github.com/loss-and-quick/pantum-open): 32-байтовые
кадры big-endian с сигнатурой `ASP\x01`.

`tools/deli-asp-probe.py` проверяет, отвечает ли Deli на те же кадры. Если
да — `install-scanner.sh` собирает backend из pantum-open с патчем из
`sane/patches` и сканирование работает через обычный SANE. Если нет —
варианты перебраны в [docs/03-scanning.md](docs/03-scanning.md).

Патч нужен по двум причинам: в конфиг добавляется идентификатор `300e:10c4`,
а backend перестаёт считать, что сканер всегда на интерфейсе 1 с
эндпоинтами `0x02/0x82`. У Deli интерфейс принтера — первый (это видно в
адресе CUPS: `usb://Deli/M3100D?serial=...&interface=1`), значит сканер на
другом номере, и backend теперь ищет его в дескрипторе конфигурации.

## Что проверено, а что нет

Проверено на машине сборки:

* все три PPD проходят `cupstestppd` без замечаний;
* фильтр отрабатывает на Ghostscript 10.02 во всех ветках — PCL-XL, PCL5e,
  PostScript, произвольный размер бумаги, приём задания через stdin,
  дуплекс в обоих режимах (для PCL5 проверено, что команда `ESC&l1S`
  оказывается в потоке);
* патч ложится на pantum-open коммита `cd25c1d4`, backend собирается без
  предупреждений, устанавливается и подхватывается SANE (`dlopen` проходит);
* `install-scanner.sh` и его `--uninstall` проверены целиком.

Не проверено, потому что самого МФУ у меня нет:

* какой язык печати аппарат принимает на самом деле — это и выясняют
  `tools/deli-devid.py` и `tools/deli-pdl-test.sh`;
* отвечает ли сканер на протокол ASP — это выясняет
  `tools/deli-asp-probe.py`;
* поля блока настроек сканера (разрешение, окно, цвет) у Deli могут стоять
  по другим смещениям, чем у Pantum: тогда сканирование пойдёт, но,
  например, с неверным размером области. Пробный скан это сразу покажет.

Отчёт `tools/deli-probe.sh` содержит ровно то, чего не хватает, чтобы
довести настройку до конца: сведения о железе, пакетах и очередях печати,
без паролей и личных данных.
