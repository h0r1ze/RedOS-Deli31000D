# Шаг 1. Что рассказать о себе может само устройство

Ничего из описанного здесь ничего не меняет в системе — только читает.

## Полный отчёт одной командой

```sh
sudo ./tools/deli-probe.sh -o deli-report.txt
```

Собирает версию системы, версии CUPS/SANE/Ghostscript, вывод `lsusb -v`,
карту USB-интерфейсов, строку Device ID, ответы по PJL, списки очередей
CUPS и устройств SANE, состояние SELinux. Файл можно целиком приложить к
вопросу: паролей и личных данных в нём нет.

## Строка Device ID — главный ответ про печать

```sh
sudo ./tools/deli-devid.py --pjl
```

Печатает то, что аппарат сообщает о себе по стандарту IEEE-1284:

```
MFG  Deli
MDL  M3100D
CMD  PJL,PCLXL,PCL,...
```

Поле `CMD:` — список языков, которые устройство принимает. По нему и
выбирается PPD:

| в CMD: встречается      | ставить                       |
|-------------------------|-------------------------------|
| `PCLXL`, `PCL6`         | `ppd/Deli-M3100D-pclxl.ppd`   |
| `PCL`, `PCL5`           | `ppd/Deli-M3100D-pcl5e.ppd`   |
| `POSTSCRIPT`            | `ppd/Deli-M3100D-ps.ppd`      |
| `ZJS`, `GDI`, `PL`      | обычный PPD не подойдёт — [docs/02-printing.md](02-printing.md) |

Того же самого можно добиться и без скрипта:

```sh
cat /sys/class/usbmisc/lp0/device/ieee1284_id
```

Если файла нет — значит, устройство держит CUPS (его USB-backend забирает
аппарат у модуля `usblp`). Тогда `systemctl stop cups`, повторить, потом
`systemctl start cups`.

Бывает и так, что `CMD:` пустое или там незнакомое слово. Это не тупик:
язык определяется опытом, см. [шаг 2](02-printing.md#если-язык-неизвестен).

## Карта USB-интерфейсов — главный ответ про сканер

```sh
sudo ./tools/deli-asp-probe.py
```

Первым делом печатает разбор дескрипторов, примерно так:

```
интерфейс 0 alt 0: ff/ff/ff — vendor-specific; эндпоинты: 0x01/bulk/out 0x81/bulk/in
интерфейс 1 alt 0: 07/01/02 — принтер (двунаправленный); эндпоинты: ...
```

Что здесь важно:

* **`07/01/02`** — обычный интерфейс принтера, с ним работают CUPS и
  `usblp`. Именно его номер CUPS показывает в адресе устройства
  (`...&interface=1`).
* **`07/01/04`** — IPP-over-USB. Если такой есть, аппарату вообще не нужны
  ни PPD, ни backend: ставится `ipp-usb`, и печать со сканированием
  работают «из коробки» (eSCL). Проверьте это в первую очередь.
* **`ff/ff/ff` с парой bulk-эндпоинтов** — почти наверняка сканер. Его
  номер и эндпоинты скрипт определяет сам и дальше пробует протокол.

После карты интерфейсов скрипт пытается заговорить со сканером: блокирует
его, читает блок настроек, спрашивает про автоподатчик и отпускает. Каретка
при этом не двигается. В конце печатается вывод — ставить backend или
искать другой путь ([docs/03-scanning.md](03-scanning.md)).

## Если устройства не видно вообще

```sh
lsusb | grep -i 300e        # есть ли аппарат на шине
dmesg | tail -20            # что сказало ядро при подключении
lpinfo -v | grep -i deli    # видит ли CUPS
```

Пустой `lsusb` — вопрос к кабелю, питанию и режиму USB на панели аппарата,
драйверы тут ни при чём.
